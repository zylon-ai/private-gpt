Use this together with [Tools](/api-guide/tools) for request examples.

---

## Supported web tools

Built-in web tools include:

- `web_search_v1`
- `web_fetch_v1`
- `GET /v1/tools/web-capabilities`
- `/v1/tools/web-search`
- `/v1/tools/web-fetch`

`web_extract_v1` remains accepted as a legacy alias for `web_fetch_v1`.

---

## How to install

The `core` and `tools` extras include the MCP client for Parallel search.
For a minimal install, add `private-gpt[tool-mcp]` if the server reports that
the dependency is missing. For local URL fetching, install
`private-gpt[tool-web-scraping]` and download the required browsers:

```bash
playwright install
```

## Settings reference

### Enable web fetch

`web_fetch_v1` and `/v1/tools/web-fetch` require `web_fetch.enabled: true`.

```yaml
web_fetch:
  enabled: true
  timeout_seconds: 15
```

---

### Search with Parallel

On a standard online install with the bundled settings and no search
configuration, Parallel MCP provides keyless search. The default `simple_text`
processor returns excerpts directly from Parallel. URL fetching is controlled
separately by `web_fetch.enabled`.

Workbench starts new chats with Web off. Open the chat’s **Tools** menu to see
the provider and enable Web. A query is sent to `https://mcp.parallel.ai/mcp`
when a model actually calls `web_search_v1`, or when an API client explicitly
calls `POST /v1/tools/web-search` with a query. A model-generated query can
include information from the conversation. `GET /v1/tools/web-capabilities`
reports the effective provider and local tool availability without sending a
search query.

Anonymous searches use Parallel MCP’s free-tier limits. If Parallel limits a
request, the tool returns a search error. Try again later or set
`PGPT_PARALLEL_API_KEY` for authenticated access and its associated limits.

<Note>
  An upgrade that picks up the new bundled settings can make direct search
  available whenever the deployment has left search unconfigured. Set
  `PGPT_WEBSEARCH_ENABLED=false` or `web_search.enabled: false` to keep search
  disabled. Set `PGPT_OFFLINE_MODE=true` to block live search and URL fetching.
</Note>

### Choose a different provider

Set the provider and enable search in your backend configuration. For example,
Brave with the `best_links` result processor also needs URL fetching:

```yaml
web_fetch:
  enabled: true

web_search:
  enabled: true
  provider: brave
  processor: best_links

brave:
  api_key: ${PGPT_BRAVE_API_KEY:}
```

For a fixture-only workflow, choose `mock` with `processor: simple_text`.
You can also set `PGPT_WEBSEARCH_PROVIDER` and `PGPT_WEBSEARCH_ENABLED` when
using the bundled configuration.

### Settings

| Setting | Description |
|---|---|
| `web_fetch.enabled` | Enables URL fetching and text extraction. |
| `web_fetch.timeout_seconds` | Timeout for fetching a page. |
| `web_search.enabled` | Enables web search. |
| `web_search.provider` | Search provider. Built-in options are `brave`, `mock`, and `parallel`. |
| `web_search.processor` | Post-processing strategy for results. |
| `web_search.num_links` | Maximum number of fetched search results. |
| `web_search.mode_quality` | Preset that controls the fast vs accurate parameter block. |
| `web_search.cached` | Enables caching for repeated searches. |
| `web_search.context_token` | Optional token budget used by the result processor. `0` disables the limit. |
| `brave.api_key` | Brave Search API key. Required when using `provider: brave`. |
| `brave.rate_limit` | Minimum seconds between Brave API requests. |
| `parallel.api_key` | Optional Parallel API key. |
| `parallel.timeout` | Timeout in seconds for searching with Parallel. |
