---

This is the recommended installation method for developers who want to run PrivateGPT against an existing LLM server (Ollama, LM Studio, etc.) without cloning the repository.

<Note>
  PrivateGPT package files are hosted at `https://wheels.privategpt.dev/packages/`. `uv` uses that location to find the PrivateGPT release and continues to resolve public dependencies from PyPI by default.
</Note>

---

## Install

<Tabs>
  <Tab title="macOS (Homebrew)">
    ```bash
    brew tap zylon-ai/tap
    brew install private-gpt
    ```

    Upgrade:
    ```bash
    brew upgrade private-gpt
    ```
  </Tab>
  <Tab title="uv (recommended, any platform)">
    [`uv`](https://docs.astral.sh/uv/) installs PrivateGPT in an isolated environment and puts the `private-gpt` CLI on your path.

    ```bash
    # Install the core package
    uv tool install  --python 3.11 \
      --find-links https://wheels.privategpt.dev/packages/ \
      "private-gpt[core]"
    ```

    Install `uv` first with the official standalone installer from `astral.sh/uv`.

    Add explicit extras only when needed, for example `private-gpt[core,queue]`.

    Upgrade:
    ```bash
    uv tool upgrade \
      --find-links https://wheels.privategpt.dev/packages/ \
      private-gpt
    ```
  </Tab>
</Tabs>

## Reproducible install (pinned dependencies)

The commands above install the newest compatible version of each dependency. To install exactly the dependency versions a release was tested with (the Homebrew formula already does this), add that release's constraints file:

<Tabs>
  <Tab title="macOS / Linux">
    ```bash
    VERSION=1.1.0
    uv tool install --python 3.11 \
      --find-links https://wheels.privategpt.dev/packages/ \
      --constraints "https://wheels.privategpt.dev/constraints/private-gpt-${VERSION}-constraints.txt" \
      "private-gpt[core]==${VERSION}"
    ```
  </Tab>
  <Tab title="Windows (PowerShell)">
    ```powershell
    $VERSION = "1.1.0"
    uv tool install --python 3.11 `
      --find-links https://wheels.privategpt.dev/packages/ `
      --constraints "https://wheels.privategpt.dev/constraints/private-gpt-$VERSION-constraints.txt" `
      "private-gpt[core]==$VERSION"
    ```
  </Tab>
</Tabs>

### Offline bundle

Each [GitHub release](https://github.com/zylon-ai/private-gpt/releases) includes a `private-gpt-<version>-core-<platform>` archive for Linux x86_64 and arm64, macOS arm64, and Windows x86_64. It contains every pinned wheel, so the install needs no network access and does not depend on PyPI staying available. Only Python 3.11 is required:

<Tabs>
  <Tab title="macOS / Linux">
    ```bash
    tar xzf private-gpt-1.1.0-core-linux-x86_64.tar.gz
    cd private-gpt-1.1.0-core-linux-x86_64
    python3.11 -m venv ~/private-gpt-venv
    ~/private-gpt-venv/bin/pip install --no-index --find-links wheelhouse \
      --require-hashes -r requirements.txt
    ~/private-gpt-venv/bin/private-gpt serve
    ```
  </Tab>
  <Tab title="Windows (PowerShell)">
    ```powershell
    Expand-Archive private-gpt-1.1.0-core-windows-amd64.zip .
    cd private-gpt-1.1.0-core-windows-amd64
    py -3.11 -m venv $HOME\private-gpt-venv
    & $HOME\private-gpt-venv\Scripts\pip.exe install --no-index --find-links wheelhouse `
      --require-hashes -r requirements.txt
    & $HOME\private-gpt-venv\Scripts\private-gpt.exe serve
    ```
  </Tab>
</Tabs>

`--require-hashes` checks every file against the SHA-256 recorded at release time.

<Note>
  **Python 3.11 is required.** PrivateGPT does not support Python 3.10 or 3.12+. With `uv`, `--python 3.11` downloads a managed interpreter if none is installed.
</Note>

## System dependencies

PrivateGPT starts without any of these, but some document features need native tools. The Docker image and the Homebrew formula already include `libmagic`.

| Tool | Used for | macOS | Debian / Ubuntu | Windows |
|---|---|---|---|---|
| `libmagic` | Detecting file types from content | `brew install libmagic` | `sudo apt install libmagic1` | Not available; PrivateGPT falls back to file extensions |
| LibreOffice | Converting `.doc`, `.ppt`, `.xls` files | `brew install --cask libreoffice` | `sudo apt install libreoffice` | [Installer](https://www.libreoffice.org/download/), with `soffice` on `PATH` |
| Ghostscript | Rendering slides to images | `brew install ghostscript` | `sudo apt install ghostscript` | [Installer](https://ghostscript.com/releases/), with `gs` on `PATH` |

## Run

After installing, set `OPENAI_API_BASE` to your LLM server and start:

<Tabs>
  <Tab title="macOS / Linux">
    ```bash
    OPENAI_API_BASE=http://localhost:11434/v1 private-gpt serve
    ```
  </Tab>
  <Tab title="Windows (PowerShell)">
    ```powershell
    $env:OPENAI_API_BASE = "http://localhost:11434/v1"
    private-gpt serve
    ```
  </Tab>
  <Tab title="Windows (CMD)">
    ```cmd
    set OPENAI_API_BASE=http://localhost:11434/v1
    private-gpt serve
    ```
  </Tab>
</Tabs>

PrivateGPT starts on port `8080` by default. Change it with `private-gpt serve --port <port>`.

## Data storage

All application data (vector store, ingested documents, models, caches) is stored under a single home directory:

| Platform | Default path |
|---|---|
| macOS / Linux | `~/.local/share/private-gpt/` |
| Windows | `%LOCALAPPDATA%\private-gpt\` |
| Docker | `/home/worker/app/` (fixed) |

Override the location with `PGPT_HOME`:

```bash
PGPT_HOME=/data/private-gpt private-gpt serve
```

## Key environment variables

| Variable | Default | Description |
|---|---|---|
| `OPENAI_API_BASE` | `https://api.openai.com/v1` | Base URL of your OpenAI-compatible LLM server |
| `OPENAI_API_KEY` | _(empty)_ | API key, if your server requires one |
| `OPENAI_EMBEDDING_API_BASE` | same as `OPENAI_API_BASE` | Override for the embeddings endpoint |
| `PORT` | `8080` | Port the server listens on (also settable via `private-gpt serve --port`) |
| `PGPT_HOME` | `~/.local/share/private-gpt` | Root directory for all local data (vector store, models, caches) |
| `PGPT_LLM_AUTO_DISCOVER_MODELS` | `true` | Discover LLM models from `/v1/models` on startup |
